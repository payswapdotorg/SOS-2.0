# SOS 2.0 Architecture Lock

STATUS: FROZEN

Ordinary implementation may not redefine:
- Constitution semantics
- Mission authority
- Value precedence
- Context semantics
- System State identity
- Semantic Spine
- architecture/implementation correspondence
- Evidence truth states
- causal evidence semantics
- Candidate lifecycle
- Assurance authority
- Experiment semantics
- Decision/ASK semantics
- Package maturity
- diversity/exploration guarantees
- self-evolution boundary

Forbidden shortcuts:
- architecture encoded only in prose
- second semantic/evidence/package authority
- stable identity based only on filenames/classes
- one analyzer treated as architectural truth
- tests treated as the entire evidence model
- unavailable telemetry interpreted as zero
- confidence alone authorizing risky changes
- package promoted after one lucky success
- composition probabilities multiplied without justified independence
- universal package winner replacing a diverse repertoire
- package reuse bypassing compatibility or assurance
- unmerged work used as a dependency
- workers changing frozen contracts silently
- LLM approving its own output

Frozen changes require:
Architecture Change Request -> impact analysis -> research/evidence -> Architect approval -> contract update -> dependent Work Orders reconciled.
