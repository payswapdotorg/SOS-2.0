# Architecture Change Process

A frozen semantic change is never hidden inside implementation.

Triggers include changes to:
- authority
- Mission semantics
- System State semantics
- Semantic Spine
- architecture/implementation correspondence
- Evidence semantics
- causal semantics
- candidate lifecycle
- assurance boundary
- package maturity semantics
- diversity/exploration guarantees
- self-evolution boundary

ACR contents:
id, motivation, current rule, proposed rule, affected artifacts, research basis, compatibility impact, migration plan, worker impact, verification plan and rollback plan.

Approval:
Architecture Change Request -> impact analysis -> evidence/research -> Architect approval -> contract update -> dependent Work Orders reconciled.
